# 1 目標

## 1.1 本期要支援哪些業務
本期支援下列業務。完整範圍（包含、依賴、排除）見第 3 章 3.3。
| 業務 | 說明 | 需求鍵 |
|---|---|---|
| 職缺建立與送審 | 用人主管與招募人員建立職缺並送審 | SCOPE-001 |
| 職缺核准 | 依開缺人數走一層或兩層核准 | SCOPE-002 |
| 職缺暫停、恢復與關閉 | 招募人員可暫停、恢復、關閉職缺 | SCOPE-003 |
| 職缺補足標示 | 已錄取人數達到開缺人數時自動標示補足 | SCOPE-004 |
| 職缺相關通知 | 送審、退回、核准、補足時通知相關人員 | SCOPE-005 |

## 1.2 成功指標
本期在下列四項都成立時算成功：
1. 業務情境都能走完：第 9 章 9.1 的每個驗收情境，業務人員都能照步驟操作到結束。
2. 每個需求都已確認或已登記為假設：第 4 章需求索引的每一條需求（確認狀態為「排除」者除外），確認狀態是「已確認」，或「相關假設」欄指向一筆假設。
3. 假設全部收斂：第 7 章 7.2 每筆假設的狀態都是「已關閉」。
4. 業務驗收通過：第 9 章 9.1 的每個驗收情境，在 9.2 都有「通過」的最新紀錄。

## 1.3 不是目標
本期不追求下列事項：
- 不追求與舊系統完全等價：舊系統有、來源 Spec 沒寫的行為，本期不做。
- 不做來源 Spec 沒寫的業務：來源沒寫的業務行為不寫成需求，改登記假設（見第 7 章）。
- 不談系統設計：資料怎麼存、系統怎麼做、怎麼與其他系統串接，不在本文件。

| 排除項目 | 需求鍵 |
|---|---|
| 對外招募網站 | SCOPE-008 |
| 面試排程 | SCOPE-009 |
| 應徵者管理與錄用作業 | SCOPE-010 |
| 舊有紙本職缺申請單的轉入 | SCOPE-011 |
