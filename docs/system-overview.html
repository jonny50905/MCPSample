WHY ─ 解決什麼問題

把「只存在老同事腦中和百萬行程式裡」的業務邏輯，變成問得到的知識

過去「免役選項背後跑什麼邏輯？」→ 翻程式數天，或找還記得的人
→
現在用中文問 AI → 它檢索程式與 DB → 幾分鐘給答案
→
而且可信每個結論附「檔案:行號」證據，並經獨立稽核驗證
機密不出公司地端模型＋內網 MCP，程式碼與資料零外流
答案附證據結論標註出處與可信度，杜絕 AI 憑空編造
知識會累積查過的物件歸戶到知識庫（wiki），越用越快越準
錯誤會記取答錯經指正後進入教訓機制，之後不再犯
ARCHITECTURE ─ 系統架構

分層分工：主控不碰資料，專家各查各的，稽核員獨立驗證

主控 AI 的記憶空間很小，所以它只負責「派工與彙整」；真正的檢索由各專家 在自己的獨立空間完成，只把結論＋證據交回來。

HOW ─ 同事使用指南

四種情境，各走各的路

記住一件事就好：問問題用 PS MODE、產文件打指令。其餘都是變化。

情境 A我想問一個業務問題
1按 Tab 切到 ps-orchestrator（PS MODE）
2直接用中文問，愈具體愈好
3例：「兵役狀態有哪些選項？選了免役之後系統會做什麼？」
得到：業務語言的答案＋每個結論的證據（檔案:行號）與可信度標註
情境 B我要某領域的完整文件
1打 /ps-research 轉職（任何領域詞都行）
2它自動盤點功能清單 → 逐一深查 → 寫成文件
3中斷沒關係——重打同一指令會接著跑，不重工
得到：docs/ps-research/轉職/ 資料夾——總覽＋逐功能文件＋稽核報告
情境 C我要查資料表的內容
1按 Tab 切到 build（一般模式）
2請它查，它會直接連 Oracle
3例：「查 PS_XXX 裡 EMPLID=123 的資料」
得到：查詢結果表格。（臨機查詢請走這裡，別用 PS MODE）
情境 D它答錯了
1直接指正——它會重新查證，不會盲目附和
2確認真的錯 → 打 /ps-lesson 一句話描述 登錄教訓
3本機立即生效；PR 合併後全團隊不再犯同類錯
得到：當下的更正答案＋長期的系統改善（跨 session 記取教訓）

指令速查表

指令用途誰會用到

GOVERNANCE ─ 權責與安全

一般同事只要會對話；管理動作全部有 SOP

角色做什麼依據
一般使用者對話問答、產文件、跑稽核、登錄教訓——全部在 OpenCode 內完成本頁情境 A–D
管理者批准教訓套用、lint 健檢、內部 git 版控、回滾、人工修正標記SOP.md（8 份核取清單）
唯讀為預設問答模式零寫入權限；資料庫僅允許 SELECT，附列數上限與逾時保護
權限白名單每個 AI 專家只拿得到自己需要的工具，越權在物理上不可能
版控與回滾產出進「內部」git（嚴禁外部遠端），任何損壞可回滾
人在關鍵環節規則變更以內部 git PR 人審把關；檔名變更一律人工確認
